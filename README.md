## Chapter II
## Общая информация
### Токен, сессионный токен, токен обновления

**Токен** является уникальной последовательностью символов и заменяет собой логин и пароль пользователя для предотвращения утечек конфиденциальной информации. Токены имеют определенное время действия, по истечению которого перестают работать.

**Сессионный токен** предоставляет пользователю права на выполнение доступных ему действий в течение сессии. Является многоразовым и имеет короткий срок действия.

**Токен обновления** продлевает срок действия сессионного токена. Является одноразовым и имеет длительный срок действия.

### Задание 1. Изменение basic авторизации на jwt
- Создайте модель JwtRequest, у которой будет логин и пароль
- Создайте модель JwtResponse, у которой будет тип, accessToken, refreshToken
- Создайте модель RefreshJwtRequest, у которой будет refreshToken

- Реализуйте структуру JwtProvider, у которой есть следующие методы:
  - Метод генерации accessToken по User, в токен необходимо сохранить информацию о UUID
  - Метод генерации refreshToken по User, в токен необходимо сохранить информацию о UUID
  - Метод валидации accessToken
  - Метод валидации refreshToken
  - Метод получения UUID из токена

- Обновите сервис авторизации, который использует UserService, JwtProvider для реализации следующих методов:
  - Измените метод авторизации, теперь он принимает JwtRequest и возвращает JwtResponse
  - Создайте метод обновления accessToken, который принимает refreshToken и возвращает JwtResponse
  - Создайте метод обновления refreshToken, который принимает refreshToken и возвращает JwtResponse

- Обновите контроллер авторизации, у которого добавятся или изменятся endpoint'ы:
  - Для авторизации пользователя
  - Для обновления accessToken
  - Для обновления refreshToken

- Измените логику определения авторизованного пользователя:
  - Получите токен из заголовка Authorization, который содержит "Bearer {accessToken}"
  - С помощью JwtProvider провалидируйте токен
  - Установите авторизацию с помощью метода sign у расширения jwt для Request.

- Уберите basic авторизацию из Authentication
- Добавьте bearer авторизацию в Authentication
- Используйте JwtProvider для валидации токена
- Если валидация прошла с ошибкой, то добавьте в ответ 401 код и не выполняйте запрос

- Добавьте доступ без авторизации к endpoint'у обновления accessToken
- Добавьте endpoint для получения информации о пользователе по accessToken

### Задание 2. Добавление поддержки истории игр
- Добавьте в модель игры ее дату создания
- Опишите запрос базы данных для получения всех завершенных игр по UUID пользователя
- Игра считается завершенной, если у нее одно из состояний:
  - Победа игрока с UUID
  - Ничья
- Добавьте в сервис для работы с играми метод для получения всех завершенных игр по UUID пользователя
- Добавьте endpoint для получения всех завершенных игр по accessToken, доступ к которому есть только у авторизованных пользователей

### Задание 3. Добавление поддержки таблицы лидеров
- Создайте модель для информации о выигранных играх, в которой будет UUID пользователя и соотношение побед
- Опишите запрос базы данных, в котором:
  - Получите соотношение количества выигранных игр к поражениям и ничьим для каждого пользователя
  - Отсортируйте по убыванию соотношение побед
  - Выберите первые N записей, в каждой из которых будет UUID пользователя и соотношение побед
- Добавьте в сервис для работы с играми получение первых N лучших игроков
- Добавьте endpoint для получения первых N лучших игроков, который принимает N(количество лучших игроков) и возвращает список лучших игроков (UUID и логин) с их соотношением побед
- endpoint для получения лучших игроков должен быть доступен только авторизованным пользователям
